# Technical audit and experimental acceptance ledger — 2026-11-04

## Evidence baseline

The public fork's `main` was `17280b53ff19ea9f62428f3f5990f4b5f60141e9`
at this audit's start. The separate builder remained **private**, at
`0230ca5954914237236cdd2780f87441ac0c3da3`. Its real game build
`41364325695` succeeded. The user installed the result on an iPad A16 and
reported boot/gameplay, purple artifacts and intermittent stutter. There are
no attached device traces, measured NXNative FPS, latency measurements,
thermal curves or screenshots identifying the failing pass. No previous
MeloNX figure is a valid NXNative baseline.

The source base is the Windows fork at
`269d61ff974b2e8e073d7357466ae130c3f6812f`. Current seedds `main` was
`975bb4c14456d145eb3d969814534eecdd996ce9` when checked. These are different
baselines and translation chains. Replacing the renderer wholesale with the
latest upstream is not a controlled performance experiment.

## Architecture and bottleneck review

| Area | Existing mechanism / concrete observation | Decision and required evidence |
|---|---|---|
| Guest CPU | Rewritten ARM64 code, Horizon HLE services, build-ID-gated cuts | No JIT requirement for this path. Keep patches isolated and verified; do not guess offsets or shrink the guest heap blindly. |
| CPU compilation | iOS previously used `-mcpu=apple-a16` for every device | Use an A14 instruction-set floor plus A16 tuning; compilation is not A14 gameplay validation. |
| Scheduling | Guest priorities/QoS, a separate encoding thread, bounded BC and prep workers | Keep two workers by default. Measure 1/2/4; no speculative adaptive manager or arbitrary core affinity. |
| Synchronization | Dirty-page protection raced pool retirement | Integrate the independently reproduced descriptor-lifetime correction. Fault/pre-write paths still avoid that mutex. Device effect is unknown. |
| GPU submissions | Segmented command buffers, encoder recording, fenced upload slots | Retain ordering and barriers. Removing them without dependency proof can corrupt pictures. Use GPU/submit/wait traces first. |
| Same-pass feedback | Targeted snapshots already exist; snapshotting all BOTW draws is expensive | Do not globally disable correctness snapshots or enable `all`. Identify a failing shader before changing its profile. |
| Texture formats | Native BC when supported; otherwise ASTC4x4 for BC1/2/3/7, R8/RG8 for BC4/5 and HDR alternatives | Keep capability-driven selection and reject forcing native BC on an incapable GPU. Never treat BC6H HDR or BC5 normals as ordinary LDR color. |
| GPU-written BC4 | Integer block views do not have complete software-BC backing semantics | Open correctness gap. A general fix needs raw-block lifetime/copies/partial updates, not just an unsigned decode kernel. |
| BC conversion | Exact packing optimization, serial small levels, bounded large-texture participants | Existing byte goldens and independent decoders are useful correctness evidence; x86 component speedups are not A16 FPS. Add real conversion time/counts. |
| Texture disk cache | Source/layout/revision keys, output hash, 256 MiB disk budget, one 16 MiB write | Keep integrity and pressure limits. Measure hit rate and lookup cost before changing budgets/eviction. Cache hits do not remove first-use shader compilation. |
| CPU staging | Three fenced slots, up to 8 MiB retained per slot | Keep reuse fences. No donation/discard of still-readable guest texture bytes. |
| Pipelines | Seed and learned prep, archives, Metal 4/hybrid pipeline paths | Keep full all-pairs prebuild off on A16. Measure prep time, runtime compilations and headroom for each budget. |
| Learned policy | Last 1024 first-discovered records, not an actual frequency ranking | Document that limitation. Collect reuse/cost evidence before introducing usage-weighted prep; 2048 is not automatically better. |
| Pacing | Display-link queue, FIFO/holds, frame-step integration | Record actual callbacks and frame IDs. A uniform 30 fps route can be better than irregular nominal 60; compare both at 720p. |
| Metrics | Existing 256-interval HUD and delayed GPU samples | Keep the HUD rolling; add a bounded full-session trace and offline percentiles. Do not label queued/generated frames as real displayed frames. |
| Memory | Runtime headroom guard, deferred releases, residency tracking | Physical RAM is not the process budget. Correlate peak footprint/headroom with hitches before adding cache or workers. |
| Thermals | Existing thermal enums, energy/process CPU logs | Record state at 1 Hz and run at least ten minutes. No inference of CPU clock or degrees Celsius from an enum. |
| Resolution | Guest handheld 1280x720 and independent 720p output default | Preserve 720p. Output scaling only reduces presentation buffers; it does not reduce all guest rendering work. |
| Input identity | Tickets and filename tags classified the base/update before extraction | Replace with internal CNMT/NCA inspection. A filename rename never validates internal metadata. |
| Builds | Existing private outputs include the rewritten modules and compiled libraries | Attempt strict host-only rebuilding from that output before downloading 17+ GiB of inputs and recompiling thousands of shaders. Refuse incompatible ABI/chain/profile reuse. |

Ryujinx and SPIRV-Cross already form the translation path. Changing their
versions changes the chain and requires real shader rebuilding. GPL projects
such as Yuzu/Atmosphere can inform architectural understanding but cannot be
copied into this MIT fork indiscriminately. No emulator's settings, per-game
60 fps patch or shader cache is assumed portable to NXNative. No Nintendo code,
shader binaries, keys or game assets are added to the public source.

## Frame generation decision

Apple's [frame interpolation descriptor](https://developer.apple.com/documentation/metalfx/mtlfxframeinterpolatordescriptor)
and [WWDC25 pipeline explanation](https://developer.apple.com/videos/play/wwdc2025/211/)
require coherent real frames, motion and depth, with correct conventions and
UI handling. Apple's feature table lists interpolation from Apple5, so **A16
must not be rejected merely because it lacks native BC**. The capability report
queries the actual MetalFX support. API support does not supply BOTW's motion
vectors or make an image-only approximation correct.

The current scan-out path does not expose validated motion vectors, matching
scene depth, jitter/camera conventions and a separately rendered UI. Passing
zeros or an arbitrary depth texture would invent inputs. An image-only optical
flow/reprojection prototype would need two histories, at least one generated
output, scene-cut/occlusion rejection, UI treatment and presentation fences.
At 1280x720, each RGBA8 image is 3.52 MiB; three extra images alone are 10.55 MiB,
before flow/depth/pyramids and driver resources. These are byte calculations,
not measured allocations or GPU time. Interpolating between two completed
30 fps frames also requires delaying presentation; input-to-display latency
must be measured independently.

**Decision:** no integrated/default frame generation in this experimental
baseline. First stabilize real 30/60 fps and identify the purple pass. The next
isolated experiment must pass synthetic motion, disocclusion, UI and scene-cut
fixtures and an A16 GPU/latency/RAM comparison. It must log real/generated/
presented rates separately and fall back to the real frame when late. A copied
flow kernel without those constraints is not a usable frame-generation feature.

## Acceptance ledger

| Change | Evidence available | Device CPU/GPU/RAM/frame-time/thermal effect | Status |
|---|---|---|---|
| Internal package identification | Synthetic grouping/decompression tests; real .NET tool compilation and CNMT boundary/digest fixtures | Build reliability only; no gameplay speed claim | Source verified; real private inputs require the new reader on a full-input build |
| Pool retirement correction | Deterministic CPU regression reproducer; existing dirty-page tests retained | Corrects a known invalid lifetime interleaving; mutex cost and iPad gameplay effect need measurement | Experimental device validation |
| Bounded stutter recorder | Concurrent producer, bounded-file and shutdown tests; sanitizer jobs | Off by default. Enabled queue about 1 MiB plus one writer; recording overhead unmeasured on A16 | Diagnostic, opt-in |
| Offline analyzer | Known percentile/tail, skipped-ticket, out-of-order, pause/window and corrupt-trace fixtures | Runs on Mac/Python, no iPad gameplay cost | Source verified |
| Hardware report / A14 ISA floor | Runtime feature queries and source compile/link checks | Allows correct capability decisions; no lower-RAM or older-device gameplay guarantee | Experimental compatibility preparation |
| HUD frame join / P99 / thermals | GPU sample keyed by actual displayed guest frame, existing rolling statistics | 1 Hz display; no device performance claim | Needs visual/device verification |
| Host-only build reuse | Strict embedded-image/ABI/profile/chain checks and round-trip fixtures | Build disk/network/time efficiency; no runtime FPS claim | Fail closed on incompatibility |
| More workers / adaptive manager / larger learned list | No comparative A16 trace | Unknown; can worsen contention, memory and sustained performance | Default changes deferred |
| Universal GPU BC4 shadows | Concrete missing semantics and unsafe candidate details | Could fix a rendering path but incomplete raw-block preservation can corrupt it | Not integrated |
| Frame generation / global snapshot or barrier changes | Input/correctness gaps; no A16 benchmark | Unknown latency, GPU and memory cost | Not enabled |
